# Удаление данных рассылки и восстановление
Подготовлено 7 октября 2026. Реальные подписчики в ходе разработки не удалялись.

## Проверенное обращение
Проверить принадлежность адреса и объём запроса. Рассылка, аккаунт Гостиной и переписка — отдельные данные. Удаление рассылки не удаляет аккаунт Гостиной.

Создать в защищённом каталоге оператора файл запроса с полями email, requestId и verifiedAt; права 600. Не передавать его в Git.
Из каталога приложения выполнить: node database/erase-newsletter-data.js --request-file /root/request.json
Без --apply это только подсчёт записей. После проверки выполнить ту же команду с --apply.

Скрипт сначала сохраняет HMAC адреса в отдельном журнале восстановления, фиксирует отзыв, удаляет бесплатную запись Ghost и проверяет её отсутствие. Только затем очищает согласия и токены; в журнале доставки удаляются email, текст ошибки и идентификатор сообщения. Ключи защиты от повторной доставки сохраняются. SQLite очищает освобождённые страницы и выполняет VACUUM.

Платные или неизвестные категории участников Ghost требуют отдельного рассмотрения. Скрипт не отменяет платные подписки автоматически.
При сбое повторить проверку и выполнение; не объявлять обращение исполненным до полного успеха. Журнал запрета сохраняется.
После выполнения создать и проверить российскую резервную копию актуального журнала запретов, убрать ненужный рабочий файл запроса и зарегистрировать исполнение без лишних данных.

## Журнал запретов
По умолчанию /var/lib/afterlogin/privacy. Файл ledger.key содержит случайный ключ HMAC и имеет права 600. erasures.jsonl содержит HMAC адреса и время обращения, без email. Это псевдонимизация, а не полная анонимность.
Журнал необходим для предотвращения восстановления удалённой подписки. Срок хранения определяется наличием старых копий и основаниями обработки; бессрочное хранение не считать согласованным.
Отправщик проверяет журнал дополнительно к согласию. При потере ключа или повреждении журнала доставка останавливается. Новое подтверждённое согласие после удаления допускает добровольную повторную подписку.

## Восстановление
До восстановления старой базы извлечь АКТУАЛЬНЫЙ журнал запретов и его ключ из наиболее новой доступной копии. Не заменять их старой версией вместе с сервером.
Оставить рассылку выключенной. Восстановить актуальный журнал, проверить чтение и повторно исполнить удаления для адресов, вернувшихся из старой базы. Сопоставление — HMAC с сохранённым ключом. Затем разрешить доставку.
Если актуальный журнал недоступен, доставку не включать до проверки истории обращений.
Восстановление Cloud Backup ещё не проверено; прежние иностранные копии и локальные архивы пока не удалены.

## Проверка
Интеграционный тест использует отдельную SQLite и локальную имитацию Ghost. Просмотр ничего не меняет; удаляется только нужный адрес; сведения другого читателя и защита от повторной доставки сохраняются; адрес отсутствует в рабочем файле SQLite после VACUUM.
