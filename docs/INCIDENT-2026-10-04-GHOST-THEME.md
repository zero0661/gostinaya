## Что пока не установлено
Имя Zapier в журнале определяет интеграцию, через которую авторизован запрос; оно не доказывает происхождение запроса с серверов Zapier. IP, User-Agent, точное время UTC и исходный процесс требуют Nginx/Cloudflare/Ghost logs. Время интерфейса истории не пересчитывать в МСК без проверки timezone.

## Риск, подтверждённый первоисточником
Официальная advisory Ghost GHSA-w52v-v783-gw97 / CVE-2026-26980:
https://github.com/TryGhost/Ghost/security/advisories/GHSA-w52v-v783-gw97

SQL injection в Content API затрагивает Ghost 3.24.0–6.19.0; исправление 6.19.1. Позволяет читать базу, включая API keys. Ghost 5.130 попадает в указанный диапазон, если нет отдельно подтверждённого backport. Это возможный путь получения ключа, а не доказанная причина именно данного инцидента.

## Порядок устранения
1. Сохранить SQL dump Ghost, content volume (включая все темы), конфигурацию Docker/Nginx и журналы. Секреты не публиковать.
2. Проверить точную Ghost/Node/MySQL версию, Docker image, compose path и резервные копии.
3. До обновления применить проверенную временную защиту reverse proxy/WAF по advisory для Content API filters с slug:[ / slug%3A%5B, учитывая риск поломки легитимных фильтров. Для гарантированного ограничения этого входа при необходимости временно блокировать внешний Content API после проверки зависимостей.
4. Обновить Ghost на поддерживаемую исправленную версию с проверкой совместимости БД и темы; не менять Docker image вслепую.
5. После закрытия уязвимости отозвать/заменить встроенный Zapier key. Проверить, используется ли он легитимной автоматизацией. Смену credential через браузер выполняет владелец.
6. Проверить остальные API keys; при замене Gostinaya 2 синхронно обновить server .env, затем проверить webhook и почтовые сценарии. Не менять только одну сторону.
7. Проверить Staff, Integrations, webhooks, code injection, содержимое статей и темы на изменения. Не считать отсутствие записей в одной странице журнала полной проверкой.
8. Проверить RU/EN, статью каждого языка, мобильное меню, Гостиную и webhook. Зафиксировать installed version и применённые меры в паспорте.
