## Работа

Systemd oneshot ghost-security-watch.service и timer ghost-security-watch.timer, интервал пять минут. Код установлен отдельно: /usr/local/lib/ghost-security-watch.py. Закрытая конфигурация, контрольный снимок и состояние уведомлений: /var/lib/ghost-security-watch, каталог 0700, файлы 0600.

Конфигурация содержит database, recipient, абсолютные node/docker paths. SMTP используется через существующий /root/gostinaya/utils/mailer.js и .env; новые SMTP credentials не создаются. Получатель — владелец проекта; адрес остаётся в конфигурации сервера, не в этом документе.

Чтение базы выполняется через docker exec ghost-db-1 с MYSQL_ROOT_PASSWORD внутри контейнера; пароль не передаётся в аргументах/выводе. Секреты API и webhook target_url сохраняются только как SHA256. Письмо сообщает названия изменённых разделов, не содержимое базы или секреты.

Проверяются: active_theme и global code injection; users без last_seen/login timestamps; roles и roles_users; integrations; api_keys metadata и fingerprint secrets; webhooks metadata и fingerprints; вставки head/foot публикаций и выбранные активные HTML-элементы (script, iframe, form, object, embed, base, on* attrs, srcdoc, meta refresh); имена каталогов тем и SHA256 обычных файлов активной темы; ссылки symlink как отдельные записи; настроенный образ и PortBindings Ghost container.

Обычные статьи без выделенных вставок или активных элементов не входят в контрольный список. Новая статья с видео, изменение формы подписки или штатная смена ключа могут вызвать ожидаемое уведомление. Контроль не устанавливает, кто сделал изменение. Исходный снимок не перезаписывается автоматически; новая конфигурация и повторный init не должны затирать прежнее состояние.

Одинаковое сохраняющееся изменение напоминается не чаще раза в 24 часа; новое состояние уведомляется при следующей проверке. При возврате к снимку приходит сообщение о восстановлении. Ошибка чтения также вызывает уведомление; если SMTP недоступен, операция завершается с ошибкой, состояние успешной доставки не записывается и следующая проверка повторяет попытку.

## Команды

Проверка: python3 /usr/local/lib/ghost-security-watch.py check

Почтовый тест: python3 /usr/local/lib/ghost-security-watch.py test-mail

Журнал: journalctl -u ghost-security-watch.service -n 30 --no-pager

Таймер: systemctl list-timers ghost-security-watch.timer --no-pager

После проверки и подтверждения легитимности конкретных изменений можно вручную принять новое состояние: python3 /usr/local/lib/ghost-security-watch.py accept. Предыдущий снимок сохраняется отдельно. Не выполнять accept вслепую после тревоги.

Остановить проверки: systemctl disable --now ghost-security-watch.timer

## Ограничения

Не предотвращает изменение и не заменяет обновления, резервные копии или внешнее наблюдение. Не обнаружит изменение, которое произошло и было отменено между опросами. Полный контроль текста статей, файлов VPS, target content symlink и внешних ресурсов не выполняется. При остановке VPS или одновременной поломке SMTP письмо отправить невозможно; нужен независимый внешний монитор. Root-компрометация позволяет выключить/подменить локальный контроль. Автоматические обновления и внешние backup этим не устанавливаются.

Локальная проверка: извлечение активного HTML, различение снимков, подавление одинаковых уведомлений, уведомление нового состояния, сохранение повторной попытки после SMTP failure, права 0600. Реальная схема Ghost, хеширование темы, SMTP доставка и systemd timer должны быть проверены при установке на VPS.
