# Alpine-01: эксплуатация после миграции 4 ноября 2026

Подробная хронология и границы проверок: [отчёт миграции](../../docs/MIGRATION-2026-11-04.md) и раздел 86 технического паспорта.

## Состав

- `compose.template.json` — схема рабочих контейнеров, закреплённые адреса внутренней сети и отдельный исходящий доступ Ghost/Гостиной. Секреты заменены обязательными переменными, это не копия приватного рабочего compose.json.
- `nginx.conf` — фактически включённая конфигурация с TLS 1.2 и сертификатом Certbot. Порты приложений не должны открываться наружу.
- `backup.py` и systemd service/timer — ежедневная зашифрованная копия с пробным восстановлением баз. RSA public key устанавливается отдельно; private key остаётся вне VPS.

## Важные пути

Рабочий Compose: `/srv/afterlogin-migration/compose.json`. Данные Ghost: `restore/ghost-content`; приложение: `restore/gostinaya`; MySQL: `mysql-data`. Приложению нужен закрытый `.env`, которого в репозитории нет. Фактически включённый файл Nginx пока называется `/etc/nginx/sites-enabled/afterlogin-preview`, хотя его содержимое уже рабочее; аналогично префикс контейнеров `afterlogin_preview` сохранён ради совместимости.

Перед использованием шаблона подготовить переменные `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD`, `MYSQL_USER`, `SMTP_USER`, `SMTP_PASS` из закрытого хранилища, каталог данных и `.env` приложения. Не генерировать новые пароли поверх существующего MySQL без согласованной процедуры. Проверить пути и адреса сети для конкретного сервера. Это сохранённая схема Alpine-01, а не универсальный установщик для произвольного VPS.

Шаблон использует фиксированные bind-каталоги, а не данные внутри эфемерных контейнеров. Никогда не удалять эти каталоги ради пересоздания контейнеров. Обновления образов и исходников выполнять отдельно, после новой проверенной копии и сравнения с реально работающей версией.

## Проверки

`docker compose -f /srv/afterlogin-migration/compose.json ps`; `nginx -t`; локальный `curl http://127.0.0.1/health` не подходит, если HTTP перенаправляет на HTTPS: проверять `/health` через локальный HTTPS с именем milenin.pro и корректной проверкой сертификата. Рабочий health-location ограничен localhost. Публичные проверки — главная, /en/, /gostinaya и страница входа; сообщения секретов и полные inspect/env в отчёты не выводить.

Сертификат: `/etc/letsencrypt/live/milenin.pro/`. `certbot.timer` и deploy-hook обеспечивают продление и reload Nginx. Пробное продление: `certbot renew --dry-run --no-random-sleep-on-renew --cert-name milenin.pro`. Обновлённые ACME-файлы и hook включаются в следующий архив через `/etc/letsencrypt`.

Копии: `/srv/afterlogin-backups`; таймер `afterlogin-alpine-backup.timer`. На Mac каталог `~/AfterLoginBackups/Alpine01`, LaunchAgent `pro.afterlogin.alpine-backup-pull`. Серверный COMPLETE не доказывает успешную внешнюю копию; нужен результат Mac verifier и last-success.json. Следить за свободным местом: автоматического удаления старых копий пока нет.

Не использовать `after-login-20261104T093630Z` как самостоятельный архив: в нём отсутствуют исходники database. Исправленная проверенная копия — `after-login-20261104T095426Z`. Исходную Beget-копию от 1 ноября не изменять и не удалять.

## Cloudflare

Итоговые A-записи milenin.pro и www: 188.137.153.152, DNS only. Прокси временно выключен по разрешению владельца из-за обрыва загрузки с Mac. Full (strict) сохранён, но при DNS only не участвует в прямом HTTPS. Не включать прокси автоматически без повторной проверки из пользовательской сети. Остальные DNS-записи и существующие VPN не входят в эту миграцию.
